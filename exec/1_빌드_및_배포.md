## 1.3 빌드 절차

### 로컬 개발 환경 (Docker Compose)

```bash
# 1. 소스 클론
git clone https://lab.ssafy.com/s14-blochain-sub1/S14P21E202.git
cd S14P21E202

# 2. 환경 변수 파일 생성
cp .env.example .env.local
# .env.local 파일을 편집하여 비밀번호 등 설정

# 3. 전체 스택 기동
docker compose -f docker-compose.local.yml --env-file .env.local up -d

# 4. 접속 확인
# Frontend: http://localhost:13000
# Backend API: http://localhost:8080
# Swagger: http://localhost:8080/swagger-ui/index.html
# RabbitMQ 관리: http://localhost:15672
```

### Backend 단독 빌드

```bash
cd BE-ssatto
./gradlew clean build -x test   # 테스트 제외 빌드
./gradlew clean build           # 테스트 포함 빌드

# JAR 파일 위치: build/libs/BE-ssatto-0.0.1-SNAPSHOT.jar
```

### Frontend 단독 빌드

```bash
cd FE-ssatto
npm install
npm run build       # dist/ 폴더에 정적 파일 생성
npm run dev         # 개발 서버 (http://localhost:5173)
```

### Docker 이미지 빌드

```bash
# Backend
docker build -t jackpotchain-be:latest ./BE-ssatto

# Frontend (GMS API 키 필요)
docker build --build-arg VITE_GMS_API_KEY=<키> -t jackpotchain-fe:latest ./FE-ssatto

# Blockchain Node
docker build -t jackpotchain-node:latest ./blockchain
```

## 1.4 배포 특이사항

### 환경 구분

| 환경 | 브랜치 | 도메인 | 배포 방식 |
|------|--------|--------|-----------|
| Dev | `develop` | `dev.ssatto777.site` | 단순 컨테이너 재기동 |
| Prod | `master` / `main` | `ssatto777.site` | Blue/Green 무중단 배포 |

### Blue/Green 무중단 배포 (Prod)

Nginx가 EC2 호스트에 직접 설치되어 있으며, Spring Boot 컨테이너 두 개(Blue/Green)를 번갈아 운영합니다.

```
ssatto777.site
      │
   Nginx (호스트)
      │ upstream.conf 기준으로 한쪽만 라우팅
      ├── spring-blue  (127.0.0.1:8090)
      └── spring-green (127.0.0.1:8092)
```

### 배포 흐름 (CI/CD)

```
Jenkins (develop/master push 감지)
  └─ Build Backend (gradlew)
  └─ Docker Build & Push (BE / FE / Node 이미지)
  └─ SSH → EC2
       └─ .env 파일의 IMAGE_TAG 갱신
       └─ deploy-prod.sh green (또는 blue)
            ├─ docker compose pull
            ├─ 공통 서비스 up (postgres, redis, rabbitmq, node, frontend)
            ├─ 대상 Spring 컨테이너 up
            ├─ health-check.sh (최대 100초 대기)
            ├─ switch-color.sh → upstream.conf 교체 + nginx reload
            └─ 배포 완료
```

### 배포 스크립트 (`scripts/`)

| 파일 | 역할 |
|------|------|
| `deploy-prod.sh <color>` | Prod 배포 진입점 (이미지 pull → 기동 → health check → 전환) |
| `deploy-dev.sh` | Dev 환경 단순 배포 |
| `health-check.sh <url>` | `/actuator/health`에 최대 20회(5초 간격) 200 응답 대기 |
| `switch-color.sh <color>` | upstream.conf 재작성 + nginx reload |
| `rollback.sh <color>` | 이전 color로 즉시 트래픽 전환 |

### 포트 구성

| 컨테이너 | 컨테이너 포트 | 호스트 포트 (로컬) | 용도 |
|----------|-------------|-------------------|------|
| Frontend (Nginx) | 80 | 13000 | SPA 서빙 |
| Backend (Spring) | 8080 | 8080 | REST API |
| Node RPC | 8776 | 9776 | 블록체인 RPC |
| Node P2P | 8777 | 9777 | P2P 통신 |
| PostgreSQL | 5432 | 15432 | 데이터베이스 |
| Redis | 6379 | 16379 | 캐시/세션 |
| RabbitMQ | 5672 | 5672 | 메시지 큐 |
| RabbitMQ 관리 | 15672 | 15672 | 관리 콘솔 |

### 장애 대응

```bash
# 즉시 롤백 (green 배포 후 문제 → blue로 전환)
~/app/scripts/rollback.sh blue

# 컨테이너 로그 확인
docker logs -f jc-spring-green
docker logs -f jc-postgresql-prod

# Nginx upstream 현황 확인
cat /etc/nginx/conf.d/upstream.conf
sudo nginx -t && sudo systemctl reload nginx
```
