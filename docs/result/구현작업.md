## 구현 상세

### 1. 개발 표준 (docs/specs/backend-specs.md)

사용자 요청에 따라 신규 생성한 개발 표준 문서:
- **테스트 주도 개발 사이클**: 핵심 로직은 테스트 먼저 작성 → 실행 → 실패 → 구현 → 재실행 → 통과 사이클 명시
- **한국어 주석 규칙**: 클래스/메서드 레벨 Javadoc 및 인라인 주석 작성 기준
- **응답 포맷**: `ApiResponse<T>` 래퍼 표준 (`code`, `message`, `data`)
- **에러 처리**: `ErrorCode` 네이밍 규칙, HTTP 상태 코드 기준, `BusinessException` 사용 원칙
- **Swagger 표준**: `@Tag`, `@Operation`, `@ApiResponses` 어노테이션 사용 기준
- **패키지 구조**: 모듈러 모놀리식 패키지 레이아웃
- **모듈 간 통신 원칙**: 직접 Repository 주입 금지, internal 인터페이스 또는 MQ 사용
- **DB/JPA 규칙**: Flyway 마이그레이션, Entity 생성 원칙
- **결과 문서화 규칙**: `docs/result/구현작업.md` 형식

### 4. 패키지 구조

기존 `ssatto.BE_ssatto` → `ssatto.jackpotchain`으로 패키지 재설계 (모듈러 모놀리식):
```
ssatto.jackpotchain
  ├── Application.java                       ← Spring Boot 진입점
  ├── global/
  │   ├── config/    (SwaggerConfig, SecurityConfig)
  │   ├── response/  (ApiResponse, PageResponse)
  │   ├── exception/ (ErrorCode, BusinessException, GlobalExceptionHandler)
  │   └── util/      (JwtUtil)
  └── domain/
      ├── blockchain/ (controller, service, repository, domain)
      ├── wallet/
      ├── exchange/
      ├── lotto/
      ├── mining/
      └── ops/
```

### 5. global 패키지 구현

#### ApiResponse<T>
- 정적 팩터리 메서드: `success(data)`, `success()`, `error(code, message)`
- `@JsonInclude(NON_NULL)` — null 필드 JSON 직렬화 제외

#### ErrorCode
- 27개 에러 코드 정의 (COMMON, AUTH, WALLET, LOTTO, EXCHANGE, MINING, BLOCKCHAIN 도메인)
- 각 코드에 `HttpStatus`와 한국어 사용자 메시지 포함

#### BusinessException
- `ErrorCode` 기반 예외
- 3가지 생성자: 기본, 추가 메시지, 원인 예외 포함

#### GlobalExceptionHandler
- `@RestControllerAdvice` 전역 핸들러
- 처리 예외: `BusinessException`, `MethodArgumentNotValidException`, `Exception` (최후 방어선)
- `BusinessException` → WARN 레벨 로깅 (스택트레이스 없음)
- 미처리 예외 → ERROR 레벨 로깅 (스택트레이스 포함)

#### SwaggerConfig
- API 기본 정보 (title, description, version)
- JWT Bearer 토큰 전역 보안 스키마
- 접근 URL: `/swagger-ui/index.html`

#### SecurityConfig
- JWT Stateless 방식 (`SessionCreationPolicy.STATELESS`)
- CSRF 비활성화
- 공개 경로: Swagger UI, `/api/auth/token`, `/api/blockchain/**`, `/actuator/health`
- 개발 단계에서 나머지 경로도 임시 허용 (도메인 구현 완료 후 `.authenticated()`로 변경 예정)

#### JwtUtil
- 지갑 주소(walletAddress)를 subject로 하는 JWT 생성/파싱/검증
- 만료 토큰 → `AUTH_TOKEN_EXPIRED` BusinessException
- 유효하지 않은 토큰 → `AUTH_TOKEN_INVALID` BusinessException
