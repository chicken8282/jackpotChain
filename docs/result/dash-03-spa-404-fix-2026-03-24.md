# DASH-03 — SPA 미정의 경로 404 안내 화면 수정

> 작성일: 2026-03-24

---

## Overview

### 무엇을 했는가

`FE-ssatto/src/App.tsx`의 `<Routes>`에 catch-all `path="*"` 라우트를 추가해, 정의되지 않은 경로 진입 시 Navbar만 있던 빈 화면 대신 404 안내 화면을 표시하도록 수정했다.

### 왜 했는가

`/unknown-route` 등 미정의 경로 진입 시 React Router가 매칭하는 라우트를 찾지 못해 `<Routes>` 내부가 아무것도 렌더링하지 않는 상태였다. 결과적으로 Navbar만 있고 본문이 비어있는 화면이 노출됐다. 사용자에게 "이 경로는 존재하지 않음"을 명확히 안내해야 한다.

구현 방식은 **A안** (인라인 NotFound 컴포넌트)을 선택했다:
- `<Navigate to="/" replace />`로 리디렉션하면 사용자가 왜 대시보드로 왔는지 알 수 없음
- 새 파일 없이 App.tsx 1개 파일 인라인으로 최소 변경 달성

---

## Changed Files

### `FE-ssatto/src/App.tsx`

**변경 내용:**

1. `PageLayout` import 추가
2. `<Routes>` 끝에 `path="*"` catch-all 라우트 추가

```diff
+import PageLayout from "./components/layout/PageLayout";

 // ... (기존 코드)

              {/* [학습 프론트엔드 v2] 추가 끝 */}
+             <Route
+               path="*"
+               element={
+                 <PageLayout>
+                   <div className="flex min-h-[40vh] flex-col items-center justify-center gap-4 text-center">
+                     <p className="font-display text-6xl font-black text-white">404</p>
+                     <p className="text-lg font-bold text-text-secondary">존재하지 않는 페이지입니다.</p>
+                   </div>
+                 </PageLayout>
+               }
+             />
           </Routes>
```

**이유:**
- `PageLayout`을 감싸 기존 페이지들과 동일한 패딩/레이아웃 구조 유지
- Navbar 하단에 적절한 여백을 두고 404 안내 텍스트 표시
- 새 파일 생성 없이 인라인 처리

### 4. JS 번들 내 404 콘텐츠 포함 확인

```
$ BUNDLE=$(curl -s http://localhost:13000/ | grep -o 'src="[^"]*\.js"' | grep -o '"[^"]*"' | tr -d '"' | head -1)
$ echo $BUNDLE
/assets/index-DEtz8n-Q.js

$ curl -s "http://localhost:13000${BUNDLE}" | grep -o '존재하지 않는 페이지입니다\.'
존재하지 않는 페이지입니다.

$ curl -s "http://localhost:13000${BUNDLE}" | grep -o '"404"'
"404"
```

빌드된 JS 번들(`index-DEtz8n-Q.js`)에 `"404"` 및 `"존재하지 않는 페이지입니다."` 텍스트가 포함됨을 확인 — PASS

React Router는 브라우저에서 `/unknown-route` 진입 시 `path="*"` 라우트를 매칭하여 404 안내 화면을 렌더링한다.
